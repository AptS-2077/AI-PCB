# OpenAI 兼容 API 接入说明

文档整理：2026-11-02。本说明描述本项目的兼容范围，不是任何平台、模型权限或真实账户可用性的保证；本次未执行远程或付费验证。

## 接入范围

远程模型配置统一使用 `provider="openai"`，密钥统一使用 `OPENAI_API_KEY`。名称表示协议兼容，不表示一定连接官方服务，也不自动识别或选择目标平台。

本项目调用 **Responses API**。兼容服务必须支持 `POST /v1/responses` 及本文所述响应格式；只支持 Chat Completions 或其他消息协议的服务不能直接接入。API 接通不扩大工程能力：实际电路仍只支持受约束的无源一阶 RC 低通，其他模板只是概念示意。

## 最短启动路径

1. 执行 `.\tools\start-local.ps1`，打开默认本地地址 `http://127.0.0.1:3000`。
2. 在「设置 → 模型 API」配置 OpenAI 兼容 API，核对目标地址，输入该目标的密钥和有权访问的模型后保存。配置运行时生效；保存成功不是连接成功证明。
3. 可显式授权后测试连接。测试发送固定 RC 需求，可能计费，不自动重试；它不等于完整 EDA 或生产验收。
4. 新建独立 RC 项目，核对远程目标与需求后授权发送。工程范围与工具配置见 `../README.md`。

密钥不要发到聊天或不可信页面。图形化输入的密钥只驻留本地服务内存，重启后须重填；更换平台或 API 地址必须重新输入与新目标匹配的密钥，不能自动复用旧目标的凭据。

## 启动环境配置

仅保留一份 `.env.example`，其中密钥为空，不包含可用或伪造的凭据。当前目录没有 `.env` 时才复制样例，不要覆盖已有文件。也可直接设置进程环境变量，或启动后在本地网页配置。

| 变量 | 约定 |
| --- | --- |
| `AI_PCB_ENGINE` | 仅 `auto`、`demo`、`openai`；默认 `auto` |
| `OPENAI_API_KEY` | 目标 OpenAI 兼容 API 的密钥；样例留空 |
| `OPENAI_BASE_URL` | 默认 `https://api.openai.com/v1`；自定义服务须使用 HTTPS 且地址以 `/v1` 结尾 |
| `OPENAI_MODEL` | 按目标平台的模型 ID 与账户权限配置；不保证程序默认模型在其他服务可用 |
| `OPENAI_REASONING_EFFORT` | 默认空，不发送；可填 `none`、`minimal`、`low`、`medium`、`high`、`xhigh`，具体支持值由目标模型决定 |
| `OPENAI_STREAM` | `true` 或 `false`；默认 `false`；SSE 由后端收齐校验后返回网页 |
| `OPENAI_OUTPUT_FORMAT` | `json_schema`（默认）、`json_object` 或 `text`；须与目标平台能力一致 |
| `OPENAI_TIMEOUT_SECONDS` | 10–300 秒，默认 90 秒 |
| `OPENAI_MAX_OUTPUT_TOKENS` | 默认 4000；可设 512–16000，或设 0 表示不发送该参数；还须符合目标模型限制 |
| `AI_PCB_ADDR` | 默认 `127.0.0.1:3000`，仅回环监听，不应暴露公网 |
| `AI_PCB_DATA_DIR` | 默认 `data/projects`，本地明文数据目录 |

`auto` 在存在非空 `OPENAI_API_KEY` 时使用远程模型，否则使用本地模板。`demo` 使用本地模板；显式 `openai` 缺少密钥时启动失败，不以演示结果冒充模型成功。启动不会自行发送模型请求，后续远程操作仍需授权。

配置优先读取进程环境变量，其次读取当前目录 `.env`，不自动读取父目录。图形化保存不写回 `.env`。手工在 `.env` 填写密钥会留下本地明文，属于操作者自行管理的启动配置；应用的“仅驻留内存”承诺不意味着这些外部文件被自动加密或删除。不得提交含密钥的文件。

## 协议与校验

```text
显式授权与配置版本校验
  → POST {OPENAI_BASE_URL}/responses
  → 完整 Responses JSON，或 SSE 中的 response.completed.response
  → 严格解析唯一方案 JSON 并校验字段、范围和方案类型
  → 受约束 RC 编译 / 工程检查，或明确标注的概念模板
  → 成功后保存项目新版本
```

认证头由后端添加，不向浏览器回传密钥。请求包含 `model`、`instructions`、`input`、`store: false`、`stream` 和 `text.format`；非空推理强度映射到 `reasoning.effort`，输出长度设为 0 时不发送长度参数。请求自包含当前完整需求和约束，不上传整个项目文件，不持久化或续传模型隐藏推理。

普通响应按输出顺序合并 assistant message 的 `output_text`，随后必须严格解析为唯一方案 JSON。SSE 必须包含唯一完整的 `response.completed`；仅有增量内容、重复最终响应、拒绝、失败、未完成、异常元数据或无效 JSON 都不能保存为项目。浏览器等待完整结果，不是逐字聊天流。

若目标平台不支持当前输出格式或推理参数，应先核对错误与平台能力，再由操作者明确修改配置并决定是否重新授权。`text` 模式仍要求严格 JSON 校验，不会通过删除解释文字、代码围栏或补全截断内容来掩盖失败。应用不自动降级格式、切换模型或重试计费请求。

## 密钥、授权与数据边界

- 每次连接测试和模型生成须显式授权；API 客户端使用 `allow_remote: true`，生成时的 `config_version` 必须匹配当前配置。界面应显示真实目标主机，不能把自定义平台标成官方直连。
- 更换 API 地址须重新提供新目标的密钥。密钥仅用于后端认证，不写项目、导出、浏览器存储或错误消息；设置与健康接口只返回脱敏状态。
- 自定义远程地址必须 HTTPS；仅回环地址允许 HTTP 供本地模拟。地址不允许用户名、密码、查询参数或片段，不能填文档页、`/responses` 或 `/chat/completions`；请求禁止跟随重定向。
- 保存设置、本地读取和健康检查不调用模型。失败不覆盖旧项目、不保存半份方案，也不自动重试；超时或失败不保证上游没有计费。
- `store: false` 是请求参数，不是兼容服务或其上游零日志、零保留的承诺。需求和工程在本地明文保存，发送前须自行确认数据可共享范围。
- 服务没有用户登录、多租户或用户级消费额度，不能作为公网服务。单并发生成限制不是完整的费用控制系统。供应商查询使用独立密钥并单独授权。

## 故障排查

| 现象 | 处理 |
| --- | --- |
| 显式远程模式启动失败 | 核对 `OPENAI_API_KEY` 和配置；也可使用 `auto` 无密钥启动，再在本地网页设置 |
| 网页显示本地模板 | 区分当前引擎与历史项目来源，查看 `/api/health` 的 `generation`；空目录不自动创建示例 |
| 上游 401/403 | 核对当前目标的密钥、账户权限和模型授权，不向其他目标转发该密钥 |
| 上游 400/404/422 | 核对 Responses 路径、模型 ID、输出格式与推理参数；只显示白名单诊断，不回显上游任意原文 |
| 429 | 按错误提示区分本地并发限制与上游限流或额度问题 |
| 504 或响应校验失败 | 原项目保留；请求可能已计费，不要连续盲目重试 |
| RC 方案被阻断 | 区分 API 错误与本地工程范围校验；独立 RC 验收应新建项目，避免累加其他不支持的旧需求 |

本地模拟协议通过不能证明真实平台可达、账户有额度或模型可用。历史记录与后续验收步骤见 `VERIFICATION.md`。
