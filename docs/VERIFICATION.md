### 历史诊断与来源边界

- API 错误诊断只展示上游状态和白名单错误码/参数，不回显任意原文、密钥或需求；失败不自动降级、修改配置或重试。历史本地模拟确认未授权操作不请求上游，授权失败仅请求一次。
- RC 阻断诊断区分模型列出的未实现需求与安全疑点。模型参数通过不代表工程检查已完成；模型判断也可能有误，不自动删除阻断项或强行放行。独立 RC 验收应新建项目，避免累加其他不支持的旧需求。
- Responses 正文按顺序合并 assistant 文本块，随后严格解析为唯一方案；SSE 必须有唯一完整终态。历史模拟覆盖分块成功与不完整/重复结果拒绝，不能据此推断真实账户曾经返回何种报文。
- 概念模板与真实 RC 工程采用不同来源提示；报告缺失时不以模板示意代替真实几何。通用解释和可复核测试见 `GENERATION_AUDIT.md`。

## 后续本地验收命令

下面是可重复使用的检查命令；本轮实际执行范围以上表为准。`board.js` 独立语法检查和发布构建未在主线程反馈中单独报告，不补记为通过。

```powershell
cargo fmt --all -- --check
cargo test --locked
cargo clippy --locked --all-targets -- -D warnings
node --check web/app.js
node --check web/board.js
node --check web/settings.js
node --test tests/board_provenance.test.mjs
```

真实 EDA 用例需要操作者配置 `AI_PCB_KICAD_CLI`、`AI_PCB_KICAD_PYTHON`，以及适用的 ngspice 路径。路径应指向实际安装的可信工具；文件存在不代表执行成功。配置后可显式运行：

```powershell
cargo test --locked --test eda_acceptance -- --ignored --nocapture
```

默认被忽略的工具链或外部输入审计用例应单独记录“未执行”，不能计入通过数量。运行服务不会热加载 Rust 或嵌入前端的源码改动；重启新构建后，图形化输入的内存密钥需要重新填写，不能把构建成功当成运行实例已更新。
