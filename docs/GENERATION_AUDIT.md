# PCB 生成来源与能力边界

公开文档整理日期：2026-11-02。文档操作未读取私人项目或调用远程模型；本轮来源测试结果依据主线程实际执行反馈，与 2026-10-20 的历史记录分开列示。

## 结论

**实际工程只支持受约束的低压无源一阶 RC 低通。** 概念模板并不根据任意需求生成可用 PCB；模型参与需求分析和模板选择，不等于完成管脚级电路设计。

概念示意不是用 PNG 覆盖结果，而是将固定器件、布局和模块级连线绘制成 SVG。同一模板、同一板尺寸下，不同需求可以得到相同外观。自定义丝印、任意器件替换、通用原理图设计、通用自动布线和生产放行没有因此实现。

## 如何区分生成来源

| 检查项 | 概念模板 | 真实 RC 路径 |
| --- | --- | --- |
| 输入处理 | 模型分析后选择参考模板，或本地模板选择 | 模型提取受约束 R/C 参数，Rust 校验并编译 |
| 电路与工程字段 | 无实际管脚级电路规格和工程报告 | `design.circuit` 保存参数，`design.engineering` 记录实际工程阶段 |
| 图形 | 固定器件与模块级示意连线，不是铜线 | 从当前工程 `pads.json` 读取真实管脚和路由几何 |
| 源文件 | 不应冒充已有 KiCad 工程 | 生成 KiCad 原理图、PCB、SPICE 及本地库 |
| 工程检查 | 概念规则检查不等于 ERC/DRC | 必须查看真实工具报告；有源文件不等于通过检查 |
| 生产状态 | 不可生产放行 | 工具通过也不生产放行，生产文件不交付 |

旧概念项目可以读取，但配置工具或更换模型不会自动将其转成真实电路。项目中记录的引擎或模型名称是来源元数据，不是当前账户已经验证的证明。

## 可复核的本地对照

`tests/generation_provenance.rs` 的常规本地回归覆盖以下区别，不需要模型密钥：

- 同模板、同尺寸的概念需求变化，不代表几何或网络会随需求重新设计。
- 在 RC 路径分别修改 R 或 C，会改变工程元件值、SPICE 和理想截止频率。
- 板尺寸不变时，RC 固定拓扑、摆放和路由可以不变；外观相似不能单独证明该路径使用了图片。
- 分别修改宽度或高度会改变 RC 板框、器件位置和布线坐标。

比较结构和数值应分开处理：器件标号、网络及 BOM 结构不能因浮点容差而被忽略；JSON 浮点序列化可能造成微小几何差异，不能将其解释为重新设计。公开说明不依赖私人项目、账户模型标识或本地部署实例作为复现前提。

可执行下列本地命令单独复核。本轮主线程在全套 Rust 测试中执行了常规来源回归，并运行 Node 来源测试；未执行默认忽略的审计用例。

```powershell
cargo test --locked --test generation_provenance
node --test tests/board_provenance.test.mjs
```

需要额外项目文件的 ignored 审计不由上述默认命令执行，也不包含在常规来源回归通过数中。不得把未运行的外部输入审计或真实 EDA 用例记为通过。

## 界面应表达的边界

- 概念项目明确显示“内置模板示意 · 未生成实际 PCB”，连线不是实际铜线。
- 概念项目原理图页明确没有 KiCad 原理图，不能暗示配置工具就能自动完成电路设计。
- 模型对话标为“需求分析来源”，不是模型已经完成 PCB 设计的声明。
- RC 来源使用 `validated-circuit-compiler-v1` 标识，仍须核对真实阶段、报告与生产门禁。
- RC 报告缺失或解析失败时，不使用概念模板替代工程预览；有几何预览也不代表 ERC、DRC 或仿真通过。
